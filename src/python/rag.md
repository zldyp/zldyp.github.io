# rag

## 向量数据库

### Chroma / LanceDB / Qdrant 对比

三者都是 RAG 最常用向量库，但架构定位完全不同：

- **Chroma** ：Python 优先，原型、Notebook、本地 Demo 首选
- **LanceDB** ：嵌入式 + 列式存储，对象存储友好，数据版本能力强，适合本地 / 边缘 / 大数据分析型 RAG
- **Qdrant** ：Rust 开发，独立服务，生产级，强过滤、高并发，中小规模线上业务首选腾讯云开发...

### 选型建议

#### ✅选 Chroma

1. Notebook、本地 Demo、快速验证 RAG 原型
2. 向量规模 **<100 万** ，本地小知识库
3. 不想部署 Docker 服务，希望 `pip install` 直接跑
4. 学习、开发调试阶段，不做线上高并发生产

> 注意：嵌入式模式下 **多进程不能同时读写同一个 Chroma 库文件** ，生产建议切换 Server 模式，但性能依然有限腾讯云开发...。

#### ✅选 LanceDB

1. 希望嵌入式、不需要常驻后台服务，但向量规模又超过 Chroma 承受上限
2. 数据存 S3 / 对象存储，需要多人共享向量数据集
3. 需要数据集版本管理、回滚，做实验对比不同 Embedding / 切分策略
4. 离线 RAG、数据分析，大数据向量集，冷热混合数据
5. 边缘场景、Serverless 函数环境

> 不适合高 QPS 线上对外服务，嵌入式模式受 Python GIL 限制。

#### ✅选 Qdrant

1. **线上生产 RAG 服务** ，有并发查询，需要稳定低延迟
2. 大量元数据过滤条件（按文档来源、时间、权限过滤检索结果）
3. 向量规模几十万～千万级别，单机可以扛住；需要备份、监控、Web 面板
4. 需要稀疏向量混合检索（ColBERT）、MMR 重排、自定义打分逻辑
5. 小团队自建向量服务，不想维护 Milvus 复杂组件栈

> 亿级超大规模集群优先 Milvus；中小规模生产 Qdrant 综合体验最好。
